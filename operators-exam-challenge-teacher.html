Lesson overview

Progression: the operators lesson taught the seven arithmetic operators, the six relational operators and and/or/not through the ferry and bakery examples. This lab is the harder follow-up: no re-teaching, more marks for choosing the right operator, precedence, brackets in logic, and printing lines in the required order.

Scope: Part A (Challenges 1–7) uses variables, constants, operators and print() only — Booleans are printed directly. Part B (Challenges 8–9) links back to the lessons Selection: if, elif, else and nested decisions and Selection: match-case, using the operators inside conditions. No loops, lists or functions anywhere. Accept any correct answer in scope.

New on the student page: a fold-out hint under the hardest questions (2c, 3c, 5, 6c, 7, 8c, 9b) and a self-score table that adds up automatically. Ask students to note which hints they opened — it shows you where support is still needed.

Challenge 1 · Predict the output

7 marks
#StatementOutputNote

Mark scheme

  • 1 mark per correct output (7). 5.0 for (b) or 9.0 for (d) earns 0.
  • Working for (g) is not marked separately, but use it to diagnose precedence errors.
Common misconceptions
  • (g) worked left to right: 10 - 4 = 6 → 6 // 3 = 2 → 2 ** 2 = 4.
  • (g) 4 // 9 given as 0.44 — // drops the fraction.
  • Reading % as a percentage.
Extension Predict 2 ** 3 ** 2 (answer 512 — ** works right to left) and -7 // 2 (answer -4 — floor division rounds down, not towards zero).

Challenge 2 · Choose the operator

6 marks
#Model lineOutput

Mark scheme

  • (a) 1 mark: // with correct output.
  • (b) 1 mark: % with correct output.
  • (c) 1 mark: an operator-only method that gives 9; 1 mark: it would also work for a number that divides exactly (e.g. 126 → 9, not 10).
    Also accept students // SEATS + (students % SEATS + SEATS - 1) // SEATS or -(-students // SEATS).
  • (d) 1 mark: /; output 24.0. Using // earns 0 — money can be a decimal.

Teaching note for (c) students // SEATS + 1 gives 9 here but is wrong when the division is exact (126 students → 10 buses). Test it with 126 live in front of the class.
Common misconceptions
  • (d) writing 24 instead of 24.0 — / always gives a float.
  • Typing 14 in the lines instead of using the constant SEATS.

3(c) [2]

Output: True. Python does and before or, so it reads it as (age >= 16 and member) or has_ticket → False or True → True. A 10-year-old with a ticket is wrongly allowed to board.

Corrected output: False.

Common misconceptions
  • Thinking Python reads logic strictly left to right.

  • Writing is_even = n % 2 = 0 (assignment inside a test).

Challenge 5 · Integrated challenge: the ferry office

10 marks

Model answer (Python 3.10)

# Ferry office
SEATS = 12
FARE = 35
CHARTER = 2000
MIN_AGE = 16

queue = 50
age = 15
has_ticket = True
with_adult = True

full_boats = queue // SEATS
left = queue % SEATS
boats_needed = (queue + SEATS - 1) // SEATS

print(full_boats)
print(left)
print(boats_needed)
print(queue * FARE)
print(CHARTER / queue)
print(left >= SEATS / 2 or left == 0)
print(has_ticket and (age >= MIN_AGE or with_adult))

Expected outputs (all tested)

queue, age, ticket, adultSeven lines
50, 15, True, True4 · 2 · 5 · 1750 · 40.0 · False · True
47, 15, True, False3 · 11 · 4 · 1645 · 42.5531914893617 · True · False
36, 17, False, False3 · 0 · 3 · 1260 · 55.55555555555556 · True · False
24, 17, True, False2 · 0 · 2 · 840 · 83.33333333333333 · True · True

Boundary test answer: a queue where queue % 12 is exactly 6 — e.g. queue = 30, 42 or 54. Line 6 is True because 6 >= 6.0. Students who wrote > instead of >= get False here — that's what the test is designed to catch.

Mark scheme

CriterionMarks
Four constants in ALL CAPITALS, used in the calculations (no retyped numbers)1
Line 1 uses //1
Line 2 uses %1
Line 3: operator-only method that works for exact and non-exact queues2
Lines 4–5: * for total fare and / for the shared charter1
Line 6: >= half a boat, or leftover == 02
Line 7: and with brackets around the or1
All seven lines printed in the required order1
Total10

Accept SEATS // 2 instead of SEATS / 2 on line 6 (both work for 12 seats). Accept the order (age >= MIN_AGE or with_adult) and has_ticket on line 7.

Common misconceptions
  • Line 3 as full_boats + 1 — fails for queue 36 (gives 4, should be 3).
  • Line 5 with // — the charter share loses its decimal part.
  • Line 6 with > — fails the boundary test.
  • Line 7 without brackets: has_ticket and age >= MIN_AGE or with_adult — a passenger with no ticket but with an adult is allowed on.
  • Writing && / ||, or true in lower case.
Extension questions (operators only)
  • Print the number of empty seats on the last boat: (SEATS - queue % SEATS) % SEATS. Why is the final % SEATS needed? (So an exact queue gives 0, not 12.)
  • Change the queue and passenger values to come from input(). Which values need int(), and how can you turn "Y"/"N" into a Boolean? (has_ticket = input("Ticket? ") == "Y")
  • Print True if the queue fills an even number of boats: full_boats % 2 == 0.
  • Explain, in one sentence each, when an exam answer should use /, // and %.

Challenge 7 · The change machine (extra)

6 marks

Model answer

# Change machine
change = 87

fifties = change // 50
rest = change % 50
twenties = rest // 20
rest = rest % 20
tens = rest // 10
rest = rest % 10
fives = rest // 5
ones = rest % 5

print(fifties)
print(twenties)
print(tens)
print(fives)
print(ones)
print(tens + fives + ones > 0)

Expected outputs (all tested)

changeSix lines
871 · 1 · 1 · 1 · 2 · True
1993 · 2 · 0 · 1 · 4 · True
501 · 0 · 0 · 0 · 0 · False
40 · 0 · 0 · 0 · 4 · True
60 (student prediction)1 · 0 · 1 · 0 · 0 · True

Mark scheme

  • 1 mark: 50s with change // 50.
  • 1 mark: remainder found with % and reused for the next step.
  • 2 marks: 20s, 10s and 5s all correct (1 mark if one step is wrong).
  • 1 mark: 1s as the final remainder.
  • 1 mark: Boolean line correct and all six lines in order.

Accept ones = rest % 5 or rest = rest % 5 then ones = rest. Accept tens > 0 or fives > 0 or ones > 0 for line 6.

Common misconceptions
  • Using change every time (change // 20) instead of what is left — 87 then gives 4 twenties.
  • Using / and getting 1.74 notes.
  • Predicting 0 · 3 · 0 · 0 · 0 for 60 (three 20s). The rule is biggest value first, so it is one 50 and one 10.
Extension Add 2 baht coins between the 5s and 1s, and print the total number of pieces of money given. For 87 the answer is 5 pieces (50, 20, 10, 5, 2 — no 1s needed).

Part B · Selection with operators

35 minutes · 18 marks · next lesson or homework

Teaching the worked examples

Show each example with the output covered. Students say the output aloud, then reveal it. Spend most of the time on these questions:

ExampleAskAnswer
1 · FaresAges 3 and 17 are both under 18. Why does 3 get 0, not 20?age < 5 is checked first and is True, so that branch runs and the rest are skipped — only the first True branch runs.
1 · FaresWhat if elif age >= 65 came first?Same results here — the branches don't overlap. Order only matters when conditions overlap (see Challenge 8).
2 · NestedWhich if does each else belong to?The one at the same indent directly above it.
3 · Last boatWhy is left == 0 checked first?0 is not >= 6 either, so it would fall into else and print the wrong message if missing.
4 · RouteWhat happens without case _ and route = "D"?Nothing is printed — no error, no output.
5 · |Can you write if day == "Sat" | "Sun":?No — in an if write day == "Sat" or day == "Sun". | belongs in case patterns.

Quick-check answers

  1. age = 5 → 20 (5 is not < 5, but is < 18).
  2. has_ticket = False → Buy a ticket (the inner if never runs).
  3. route = "b" → Unknown route — matching is case-sensitive.
Syllabus note The | pattern is shown as useful Python 3.10. Check it against the Python 3.10 guide in your syllabus; if you prefer, teach separate case lines and treat Example 5 as enrichment.

Challenge 8 · Selection: order, nesting and boundaries

10 marks

8(a) [3]

score958030
OutputPassPassFail
  • 1 mark each. Students who write Distinction for 95 have not traced the code — they've guessed what it should do.

8(b) [2]

Any score of 80 or 90+ is also >= 50, so the first branch catches it and the other elifs are never checked. Test the highest boundary first:

if score >= 90:
    grade = "Distinction"
elif score >= 80:
    grade = "Merit"
elif score >= 50:
    grade = "Pass"
else:
    grade = "Fail"
print(grade)

Tested: 95 → Distinction · 90 → Distinction · 80 → Merit · 50 → Pass · 49 → Fail.

  • 1 mark: explains the first True branch stops the checks / overlapping conditions.
  • 1 mark: corrected order (or equivalent with and ranges, e.g. score >= 50 and score < 80).

8(c) [5]

MAX_WIND = 40
CHILD_AGE = 12
wind_speed = 20
has_ticket = True
age = 10
with_adult = False

if wind_speed > MAX_WIND:
    print("Ferry cancelled")
else:
    if not has_ticket:
        print("Buy a ticket")
    else:

            print("Child must travel with an adult")
        else:
            print("Board")

Mark scheme

  • 1 mark: wind check with > MAX_WIND (not >=), using the constant.
  • 1 mark: at least one correctly nested if inside an else (or inside an if).
  • 1 mark: ticket check with not has_ticket or has_ticket == False.
  • 1 mark: child rule with < CHILD_AGE and not with_adult.
  • 1 mark: exactly one message printed for every test case.

Accept a flatter if/elif version for 4 marks max — the question requires nesting.

Common misconceptions
  • Using separate ifs, so a cancelled ferry also prints Buy a ticket.
  • wind_speed >= 40 — the boundary test catches it.
  • Indenting the inner else at the wrong level so it pairs with the outer if.
  • Writing if has_ticket = False:.
Extension Add a warning band: wind from 30 to 40 prints Board — rough sea instead of Board. Students must decide where the new elif goes.

Challenge 9 · match-case: the ticket machine

8 marks

9(a) [2]

choice holds the integer 2, but the cases are the strings "1" and "2". An integer never matches a string, so only case _ matches.

Fix: case 2: (and case 1:) — or choice = "2".

  • 1 mark: integer vs string mismatch explained.
  • 1 mark: a valid correction.

9(b) [6]

# Ticket machine
SINGLE = 35
RETURN = 60
DAY_PASS = 120
ticket = "R"
quantity = 5

price = 0
match ticket:
    case "S":
        price = SINGLE
    case "R":
        price = RETURN
    case "D":
        price = DAY_PASS
    case _:
        print("Invalid ticket")

if price > 0:
    total = price * quantity
    if quantity >= 5:
        total = total - total // 10
    print("Total: " + str(total) + " baht")
ticket, quantityOutput
S, 2Total: 70 baht
R, 5Total: 270 baht (300 − 30)
D, 1Total: 120 baht
X, 3Invalid ticket
R, 4 (predict)Total: 240 baht — no discount, 4 is under 5
S, 5 (predict)Total: 158 baht — 175 − 175 // 10 = 175 − 17

Mark scheme

  • 1 mark: match ticket with the three string cases setting the price from constants.
  • 1 mark: case _ last, printing Invalid ticket, and no total printed afterwards.
  • 1 mark: total = price * quantity.
  • 1 mark: discount condition quantity >= 5.
  • 1 mark: discount uses total // 10.
  • 1 mark: exact output format for all tests (accept print("Total:", total, "baht")).

Accept working out and printing the total inside each case, provided it is correct.

Common misconceptions
  • case S: without quotes — Python reads S as a variable name that captures any value, not the letter S, and stops with a SyntaxError because the cases after it can never be reached.
  • Printing Total: 0 baht after Invalid ticket.
  • Discount as total * 0.9 → 270.0; the question asked for // 10, whole baht.
  • quantity > 5 — the 5-ticket test catches it.
Extension Accept lower-case codes with case "S" | "s":. Then add a "F" family ticket at 100 baht that never gets the discount — students must change the discount condition to quantity >= 5 and ticket != "F".
